# V407 Digital-M effects layer (effects 37-114, palettes 31-48)

The Diff-Power Ultra Receiver Digital-Medium on the CH32V407 runs the 36 legacy effects plus the approved V407 set. This
folder is that layer; `fxv_api.h` is the contract every effect module codes against. The V203 build never compiles it.

## Files

| File | What |
|---|---|
| `fxv_api.h` | The contract: context, descriptor, working pixel, particle record, primitives, reservations |
| `fxv_core.c` | Context lifecycle: registry, palettes, the effect clock, simulation ticks, staged start, slices, render |
| `fxv_color.c` | 16-stop palette sampling, blends, natural white (kelvin), white mapping, the 16-bit packer `fxv_pack16` |
| `fxv_math.c` | Noise and the other shared maths |
| `fxv_legacy.c` | Effects 1-36 through the layer (their legacy context in the arena) |
| `b1_analytic.c` .. `b7_bursts.c` | One module per effect batch (PLAN section 5); each batch owns only its module |
| `manifest/<batch>.json` | One manifest per batch: the ids it implements and their metadata |
| `catalogue_v407.json` | The approved catalogue (input; `--import` copies a new approved file in) |
| `fxv_gen.h/.c/.json`, `pixel_fx_catalogue_v407.json` | Generated by `tools/gen_fx_tables.py --profile v407`; never hand-merge |

## The effect contract

An effect is a `fxv_desc_t` of functions on a `fxv_ctx_t`:

1. `bytes(n, tier)`: arena bytes for a run of `n` pixels; must stay `<= FXV_SLOT_BYTES(n)` = align16(12 n + 1024) for every
   n up to 800 (`test_fxv` checks it). The arena is zeroed before `init`.
2. `init(x)`: build the initial state, bounded (about 5,000 cycles; longer set-up belongs in the advance).
3. `advance_begin(x)`: once a frame, after the layer moved the clock (`x->t`, `x->et`, `x->de`, ticks). Per-frame numbers
   go in `x->u[]`; a stateful effect starts its frame job (`x->job[]`).
4. `advance_slice(x, quota)`: bounded work (about `quota` cells or particle steps, at most ~5,000 cycles); return
   nonzero while more remains. Run simulation ticks with `fxv_tick_next(x)`: it hands out the frame's ticks (at most 16;
   the rest stays as debt; a debt over 2 s of effect time restarts the effect with seed + epoch).
5. `render16(x, from, count, out)`: pixels `[from, from + count)` of the run, `count <= 32`. Read-only: any chunk order
   gives the same pixels. Positions in the virtual strip are `x->vbase + i` over `x->vlen`.
6. Optional: `destroy`, `changed` (speed / intensity / custom / colours / seed changed), `digest` (a state hash the
   goldens compare).

Palettes: every effect takes one. `x->pal_own` is 1 when the slot's palette is Effect default on an effect whose default is
its own colours (`fxv_pal_resolve`: the default-palette table holds 255 for it); then the effect draws its designed look,
untouched. Otherwise `x->pal` holds the chosen palette (0..48, or 254 = colour 1 -> 2 -> 3), built before the first slice:
`if (x->pal_own) { the designed look } else { the palette look }` (JS `x.palOwn`), the palette sampled with `fxv_pal`.
With a palette the effect keeps its motion, timing and brightness; a natural coordinate of the effect walks the whole
palette. `pal_notes/<batch>.json` carries each effect's `palette_slots` and `palette_note` (merged into the catalogue).

Rules: integer only, no division per pixel, no heap, no state outside the context, its arena and its particle range.
Random draws come from `fxv_rand(seed, tick, object)` or a per-object `fxv_rng_next` state, never render order. Working
colour is `fxv_px_t`: r, g, b at 8.8 (full = 65280, gamma comes once in the packer), `q` = the neutral white share (0..255),
`k` = its temperature (0 = 2000 K .. 255 = 6500 K, `fxv_kelvin16`). A natural-white effect sets q and k; the packer maps
that share to the strip's W / WW + CW (accurate mode subtracts the emitter's RGB equivalent); q = 0 is an ordinary colour
with the legacy auto-white.

## Manifest (one per batch)

```json
{"batch": "b1_analytic", "c": "b1_analytic.c", "js": "b1_analytic.js",
 "effects": [{"id": 38, "symbol": "kelvin_drift", "built": true, "flashy": false, "white": true,
              "tick_ms": 0, "particles": 0, "cost": {"frame": 600, "px": 90, "tick": 0, "particle": 0}}]}
```

- `symbol`: the C descriptor is `fxv_d_<symbol>`, the JS registration `fxv_def(id, '<symbol>', {...})`.
- `built`: true puts the id in the registry, the capability map (page 0x11) and the ESPHome catalogue's built map. An
  id that is not built is refused (never rendered as Solid).
- `tick_ms`: simulation tick in effect ms (0: analytic). `particles`: the cap the slab gives this effect (<= 2 x the design).
- `flashy`: may flash (Countdown 113 must be). `white`: sets q / k. `hold` (optional): on a strip under 12 pixels the
  layer holds the effect's light: a pixel may brighten at once but dims at most at a ~2 s release (fxv_core.c), for an
  effect whose local events would otherwise flash the whole of a 1-8 pixel strip (the flash gate's short lengths).
- `cost`: modeled cycles per frame, per pixel (render), per tick and per particle tick; the scheduler's particle step-down
  uses them (the packer's per-pixel cost is added by the generator). Measure and update them with the cycle tools: a
  model is conservative (the measured worst within it, every control corner, length and mode:
  `tools/measure_fxv_models.py` exits 1 on a miss). `frame` is 32 bits.
  `frame_pal`, `px_pal`, `step_pal` (optional): the same on a chosen palette (`pal_own` 0) where that costs more than the
  Effect default (`tools/measure_fxv.py` / `measure_fxv_slices.py --palette 10` and `254`, the worse); absent = equal.
  The engine plans an own-colour effect on a palette with them (`fxv_meta[id].c_frame_pal / c_px_pal / c_step_pal`).

Then run `python tools/gen_fx_tables.py --profile v407` and commit the generated files with the batch.

## Budgets (B0 measurements, tools/measure_fxv.py, rv32emu at 200 MHz)

- A frame's advance + render + pack: at most 1,000,000 cycles at the 42 fps floor; the packer costs 231-273 cycles a
  pixel (natural white on RGBW / RGBCCT 379-557), Kelvin Drift renders at ~213, Pacifica ~701. The receiver renders
  one run a step (fxv_engine_span: pixels with one top segment, one side of a mirror; a later segment covers an earlier
  one, so only the top one renders): 5,000 / (that run's cycles a pixel: its layers' `c_step` plus blend / copy /
  brightness) pixels (1-32); a crossfade 3,500 (both layers' render calls' fixed parts: `c_step` is a pixel's share at
  the effect's own step size). `cost.step` (the generator's `c_step`) is measured: keep it honest.
- Every step at most 5,000 cycles: a segment set, a dequeue, a frame start (the colour ramp; each effect's frame start,
  the fading one's too, is an engine step of its own), an engine slice (zeroing, init, advance) and a render + pack
  step; tools/measure_fxv_slices.py measures them all (every effect alone, heavy mixes, a worst-case generator,
  `--partners`: every effect to and from given ids) and exits 1 over the limit. Fire's legacy slices: ~2,200.
- Stack: `render16` runs ~1,000 B deep (main + compositor + adapter); keep an effect's own frame (locals + callees)
  under ~300 B, no large local arrays (use the arena). The tick ISR is unaffected (7,404 of 9,940 modeled cycles).
- RAM: everything lives in the arena (S(n) a context), the particle slab (`x->p[0 .. x->pn)`, the count can change
  between frames: records past `pn` are gone, new ones arrive zeroed) and `x->u` / `x->job`.
- Flash comfort: `test\build_fxv.cmd` builds `fxv_flash_check.exe`: at the defaults, 10 min at 42 fps, at most 3
  full-strip luminance excursion pairs in any second (flashy effects too), RGB 1-6 / 8 / 60 / 800, RGBW 1 / 3 / 600,
  RGBCCT 500 pixels.

## JS port

Each batch ships `dashboards-r13/v3/digital/fx/v407/<batch>.js` with the same functions under the same names
(`fx/v407/README.md`); `fx/v407/assemble.py` builds `fx/qfx.js` and `golden/v407/run.cmd <worktree>` checks C against JS
for every built id (defaults, slider corners, every palette, formats and lengths, cadences, clock wrap, jumps, chunks).
