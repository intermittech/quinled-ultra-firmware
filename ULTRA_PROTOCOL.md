# The QuinLED Ultra protocol in this firmware

The normative specification and the shared header live in the
[QuinLED Ultra protocol repository](https://github.com/intermittech/quinled-ultra-protocol) (protocol 0.3).
This firmware uses wire VERSION 3 and the matching `src/core/ultra_protocol.h`, a byte-identical copy of the
protocol release's header (`test/test_protocol_copy.py` checks it). Firmware 0.7.1 is a source release: no images
are published yet; bench qualification of the line profiles and the bootloaders comes first.

Boards 1 and 2 share the analog target renderer. SET interpolates 16-bit M,
A and B values with its transition duration, smoothstep and via-off flags.
Gamma uses the full product; min/max power, dim-to-warm and current limits apply.
Analog effects are generated by the host through repeated SETs with transitions.
Retired opcodes 03, 04 and 0A are unknown commands; their values and all analog
effect IDs remain reserved. They do not change state or acknowledged sequences.

SCENE 08 byte 0 selects power-on (0) or signal-loss (1) levels. Other selectors
are ignored atomically. Byte 1 is the fade into that level in 100 ms units;
M/A/B follow. All-zero values are dark. Both output level sets are stored only
when changed, with A/B records and dark-only flash admission. No effects are
stored. The first SET uses its own transition to take over from the shown scene.
WS takeover uses a one-second smooth fade because WS frames have no SET duration.
CONFIG 8 value 3 selects the signal-loss levels; an unset loss level fades dark.

The default signal-loss policy is hold (CONFIG 8 = 0). A momentary controller
drop keeps the last setting, and returning data resumes normally with no blink.
Off, fade-off and stored loss levels apply only when explicitly configured.

Board 1 always forwards and never answers. Board 2 serves its documented return
pages and descriptor. OUTPUTS byte 20, DIAG pending bit 0x10 and IDENTITY feature
bit 0x00010000 are reserved zero. ACKS requests for removed commands are NEVER/0.
Board 3 retains its local pixel effects, scenes, calibration and chain modes;
see [digital firmware](docs/ur_digital_m-firmware.md) and
[the pixel effects](docs/ur_digital_m-effects.md).
